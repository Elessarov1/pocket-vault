# Интеграция WASM и Telegram Storage

`vault-core` не знает о браузере. `vault-wasm` владеет открытым контейнером,
ключами и криптографическими операциями. JavaScript знает только callback API
Telegram и строки persistent-формата; он не реализует KDF или шифрование.

## Запуск

```powershell
npm run build:wasm
node scripts/serve.mjs
```

`web/src/bootstrap.js` проверяет Bot API 9.0 и наличие DeviceStorage,
загружает WASM и создаёт `VaultPersistence`. SecureStorage подключается как
необязательная возможность быстрого входа.

Production-цель включает актуальные клиенты Telegram на iOS, Android, Windows,
macOS и Linux. Хранилище локально для каждого устройства; синхронизации между
клиентами нет. В DeviceStorage записывается только шифротекст. На клиентах с
SecureStorage мастер-фраза может сохраняться отдельно в защищённом системном
хранилище до ближайшей полуночи по локальному времени устройства; при отсутствии
API приложение продолжает работать с ручным вводом.

Для локального просмотра на `localhost` создаются совместимые callback-адаптеры
в памяти. Они не используют `localStorage`, не переживают перезагрузку и никогда
не включаются как fallback внутри Telegram.

## Создание

1. Убедиться, что `vault_meta_v1` отсутствует.
2. Передать мастер-фразу в `VaultSession.create()`; WASM создаёт соль, DEK,
   обёртку ключа и первый зашифрованный слот.
3. Записать с чтением назад: первый слот, metadata, active pointer.
4. Получить открытую `VaultSession` только после успешной записи всего bundle.

## Открытие

JavaScript читает четыре значения DeviceStorage и передаёт их вместе с
мастер-фразой в `VaultSession.open()`. WASM проверяет формат, KDF bounds,
wrapped DEK и оба слота. Если active pointer отсутствует или устарел, WASM
возвращает исправленное значение, которое адаптер записывает с проверкой.

Перед автоматическим открытием адаптер проверяет `vault_manual_lock_v1`. Если
ручной блокировки нет, мастер-фраза читается из SecureStorage по ключу
`master_password_cache_v1`. Значение — JSON с версией, мастер-фразой и временем
последнего явного ввода и временем ближайшей локальной полуночи. Кэш передаётся
в обычный `VaultSession.open()` только до этой границы. Автоматическое открытие
не обновляет время; просроченное, повреждённое или старое значение без timestamp
удаляется.
Значение не копируется в localStorage или DeviceStorage. Ошибка/отсутствие
SecureStorage не делает сам клиент несовместимым.

## Смена мастер-фразы

`preparePasswordChange()` сначала проверяет текущую мастер-фразу, затем создаёт
новую соль и оборачивает существующий DEK новым KEK. JavaScript записывает новую
metadata и читает её обратно; только точное совпадение разрешает
`commitPasswordChange()`. Зашифрованные слоты с записями не меняются. После
успешного commit кэш SecureStorage заменяется новой мастер-фразой.

## Сохранение

`VaultSession.prepareSave()` создаёт шифротекст неактивного слота, но не меняет
поколение сессии. Далее адаптер:

1. записывает слот и читает его обратно;
2. передаёт readback в `verifyPendingSlot()`;
3. записывает active pointer и читает его обратно;
4. передаёт readback в `commitPendingSave()`.

Только четвёртый шаг меняет committed generation. При любой ошибке вызывается
`cancelPendingSave()`; предыдущий слот остаётся доступным, а полностью записанный
новый слот может быть найден при следующем открытии.

## Уничтожение без мастер-фразы

 Актуальная продуктовая политика разрешает уничтожение без мастер-фразы и без
биометрии после явного подтверждения в UI. `destroySession()`:

1. блокирует WASM-сессию;
2. удаляет и проверяет отсутствие всех четырёх Pocket Vault ключей в
   DeviceStorage.

Это не обещает физическое стирание резервных копий, которые могла создать ОС
или Telegram.

## Lifecycle

Обработчик события Telegram `deactivated` сначала скрывает секреты в DOM, затем
вызывает `VaultSession.lock()`. На `activated` контроллер пытается открыть
сессию через кэш SecureStorage, действующий до ближайшей локальной полуночи.
Если приложение остаётся открытым на границе дня, таймер удаляет кэш и
блокирует активную сессию в полночь.
Ручная блокировка сначала записывает `vault_manual_lock_v1`, поэтому не
отменяется этим событием и требует явного ввода мастер-фразы.

## Доступ UI к открытым данным

Контроллер получает для списка только `id`, название и временные метки. Экран
записи вызывает `getEntryDetailsJson()`, где секрет отсутствует. Отдельный
`getEntrySecret()` вызывается только после нажатия «Показать» или «Скопировать»;
показанное значение автоматически скрывается через 15 секунд и сразу удаляется
из DOM при смене экрана или событии `deactivated`.
